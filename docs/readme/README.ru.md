<h1 align="center">Luma</h1>

<p align="center">
  Лёгкий и быстрый медиаплеер для Linux на базе <b>mpv</b> и <b>Qt 6 / QML</b> (Kirigami).
</p>

> **Платформа: только Wayland.** Luma рассчитана на сессии Wayland (KWin, GNOME, Sway,
> Hyprland, …). X11 **не** поддерживается, и поддержка **не планируется**. Без сессии
> Wayland приложение отказывается запускаться.

## Возможности

- **mpv внутри** — воспроизводит практически любые видео- и аудиоформаты без
  дополнительных кодеков.
- **Несколько плейлистов** — вкладки с созданием, переименованием, удалением и очисткой,
  перетаскивание записей, добавление файлов или целой папки, «Добавить в плейлист»
  из меню записи.
- **Настройка субтитров** — шрифт, размер, полужирный, цвет текста и обводки, толщина
  обводки, фон, положение по вертикали, переопределение стиля ASS; применяется к mpv
  сразу.
- **Ссылки через yt-dlp** — откройте ссылку из меню, Luma получит прямой поток через
  `yt-dlp`. Обычные видео перематываются как раньше, а прямые трансляции переходят в
  режим прямого эфира с индикатором `LIVE` без полосы перемотки. Название видео показывается
  в уведомлении и плейлисте. SOCKS-прокси работает через локальный HTTP-мост, поэтому
  mpv не обходит прокси.
- **Chromecast** — трансляция на ТВ в локальной сети (поиск через `avahi-browse`,
  перекодирование в HLS через `ffmpeg`).
- **Картинка в картинке** — `P` или пункт контекстного меню превращает окно в
  маленький плеер без рамок (его можно тащить и растягивать; пауза, перемотка, время,
  громкость, возврат) и обратно. В KDE Plasma окно PiP остаётся поверх остальных окон.
- **Подгонка окна** — `W` или **Воспроизведение → Подогнать окно под видео** в
  контекстном меню один раз подгоняет окно под соотношение сторон видео в пределах
  текущего размера окна: оно сужается по ширине или высоте, убирая чёрные полосы, а не
  растягивается на экран. Пропорции не фиксируются: окно можно свободно менять дальше.
- **Продолжение просмотра** — локальные аудио/видео и ссылки yt-dlp продолжаются
  с места остановки после перезапуска. Прямые трансляции всегда начинаются с live-края.
  Кэш позиций ограничен по размеру и отключается в **Настройки → Общие**.
- **Главы** — переход к предыдущей/следующей главе по `PageUp` / `PageDown` или через
  меню «Воспроизведение», а также отметки глав на полосе перемотки (скрываются в
  **Настройки → Интерфейс**). Главы из ссылок YouTube тоже поддерживаются.
- **Подсказка по клавишам** — удерживайте `?` (`Shift+/`),
  чтобы увидеть все сочетания, пока клавиша нажата.
- **Управление с клавиатуры** — воспроизведение, перемотка, громкость, дорожки,
  соотношение сторон, обрезка полей.
- **MPRIS2** — управление из виджета рабочего стола и мультимедийными клавишами.
- **Интерфейс на английском и русском** — переключается на лету.

## Зависимости

Требуется сессия **Wayland**. X11 не поддерживается, и поддержка не планируется.

Для сборки:

| Зависимость | Примечание |
| --- | --- |
| Qt 6.9+ | Core, Gui, Quick, QuickControls2, Widgets, DBus, Network, Concurrent, OpenGL, OpenGLWidgets, **WaylandClient**, LinguistTools |
| Библиотеки Wayland | файлы разработки `wayland-client` и `xkbcommon` (обязательны; X11-бэкенда нет) |
| libmpv | пакет `mpv` / `mpv-libs` |
| TagLib | чтение и запись тегов аудиофайлов (`taglib`) |
| Библиотеки разработки FFmpeg | `libavformat`, `libavcodec`, `libswscale`, `libavutil` |
| CMake ≥ 3.16, Ninja (или Make), компилятор с C++17 | |

QML-модули, нужные только во время работы (CMake их **не** проверяет — приложение
падает с ошибкой импорта QML):

- `Kirigami` (`kirigami` / `kirigami2`);
- `qqc2-desktop-style` (стиль KDE для Qt Quick Controls).

Необязательно:

- `yt-dlp` — воспроизведение ссылок с видеосайтов;
- `avahi` (`avahi-browse`) и бинарник `ffmpeg` — Chromecast.

Arch Linux:

```bash
sudo pacman -S --needed base-devel cmake ninja qt6-base qt6-declarative qt6-wayland \
    kirigami qqc2-desktop-style mpv ffmpeg taglib
```

## Сборка

```bash
cmake -B build -S . -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
./build/bin/luma                       # бинарник в build/bin/, а не в build/
./build/bin/luma /путь/к/файлу.mkv     # сразу открыть файл
```

Установка в систему:

```bash
cmake -B build -S . -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=/usr
cmake --build build -j"$(nproc)"
sudo cmake --install build
```

## Пакет для Arch Linux

В репозитории есть `PKGBUILD`:

```bash
makepkg -si
```

## AppImage

Собрать переносимый AppImage:

```bash
./build-appimage.sh
# -> dist/Luma-<version>-x86_64.AppImage
```

Скрипт собирает Release-версию в AppDir и включает Qt/QML (в том числе Kirigami и
`qqc2-desktop-style`), libmpv, FFmpeg, TagLib и плагины платформы Wayland; полученный
образ работает только на Wayland. Также добавляются виджет-стиль Breeze и небольшой
набор иконок Breeze, которые использует интерфейс, поэтому скроллбары и иконки не
зависят от KDE в системе. При первом запуске скрипт скачивает `linuxdeploy`, его
Qt-плагин и `appimagetool` в `.appimage-tools/`. `ffmpeg` и `avahi-browse` не включаются;
установите их в системе для HLS-трансляции и поиска Chromecast. `yt-dlp` и
`yt-dlp-ejs` можно установить из *Настройки → Воспроизведение →
Интернет-воспроизведение*, не включая их в пакет. Deno установите системно, чтобы
yt-dlp проходил JavaScript-проверку YouTube без чтения куки браузера.

Собирайте на самом старом дистрибутиве с glibc, который планируете поддерживать:
AppImage не может включать glibc. На системах без FUSE запускайте образ с
`--appimage-extract-and-run`.

## Тесты

По умолчанию тесты **выключены** — при обычной сборке не собираются и в пакет не попадают.
Включаются явно:

```bash
cmake -B build -S . -DLUMA_BUILD_TESTS=ON
cmake --build build -j"$(nproc)"
ctest --test-dir build --output-on-failure
```

Набор на Qt Test проверяет основную логику: таблицу горячих клавиш, модель и менеджер
плейлистов, конфигурацию, журналирование и файл настроек yt-dlp. Тесты работают с временным
`XDG_CONFIG_HOME`/`XDG_CACHE_HOME`, поэтому ваши настройки не затрагиваются. Qt6::Test
необязателен: если модуля нет, тесты просто не собираются.

`tst_media_open` — интеграционный тест с настоящим libmpv в headless-режиме
(`vo=null`, `ao=null`): открывает аудио/видео из `tests/data/` и YouTube-ссылку через
поддельный `yt-dlp`. Запуск только его:
`ctest --test-dir build -R tst_media_open --output-on-failure`. Настоящая сетевая
проверка YouTube пропускается, пока не задана переменная `LUMA_TEST_YOUTUBE_URL`.

## Использование

- **Открыть файл или папку** — правый клик по видео → *Открыть*, либо перетащите файл
  в окно, либо передайте путь в командной строке.
- **Открыть ссылку** — правый клик → *Открыть* → *Открыть ссылку…*; yt-dlp
  разрешает поток, и Luma воспроизводит его в mpv. Обычные видео перематываются как
  обычно, а прямой эфир идёт без полосы перемотки и удерживается на live-крае.
- **Плейлисты** — кнопка плейлиста на панели управления открывает панель. Вкладки
  сверху переключают плейлисты; кнопка со списком слева от вкладок открывает выпадающий
  список всех плейлистов. Правый клик по вкладке — *Добавить файлы…*,
  *Добавить папку…*, *Очистить плейлист*, *Переименовать*, *Удалить*. Правый клик по
  записи — воспроизведение, перемешивание, «Добавить в плейлист», свойства, открытие
  папки с файлом и удаление из плейлиста. Для ссылок на радио вместо адреса
  показывается название станции, полученное из потока; во время воспроизведения
  показывается текущий трек. У каждого именованного плейлиста свой режим
  воспроизведения (меняется в *Воспроизведение → Режим воспроизведения*); режим из
  настроек действует только на плейлист «По умолчанию».
- **Субтитры** — выбор дорожек в контекстном меню или горячими клавишами.
- **Трансляция** — *Воспроизведение → Устройство вывода* в контекстном меню.

## Горячие клавиши

Клавиши ниже — значения по умолчанию. Их можно переназначить в
**Настройки → Клавиши**; привязки сохраняются в `~/.config/luma/shortcuts.conf`.
Для каждого действия можно задать локальную клавишу и, если рабочий стол
предоставляет `org.freedesktop.portal.GlobalShortcuts`, глобальную. Глобальные
клавиши доступны только в режиме одного экземпляра (`single_instance=true`);
при нескольких экземплярах они отключаются, чтобы не было неоднозначной
маршрутизации. Клавиша подсказки `?` намеренно не настраивается.

| Клавиша | Действие |
| --- | --- |
| `Space` | Пауза / воспроизведение |
| `←` / `→` | Перемотка назад / вперёд на 5 с |
| `Ctrl+←` / `Ctrl+→` | Перемотка назад / вперёд на 60 с |
| `Alt+←` / `Alt+→` | Предыдущий / следующий кадр |
| `↑` / `↓` | Громкость +5 % / −5 % |
| `M` | Выключить звук |
| `Q` / `E` | Предыдущий / следующий файл |
| `PageUp` / `PageDown` | Предыдущая / следующая глава |
| `S` | Панель плейлиста |
| `I` | Панель сведений о файле |
| `F` | Полноэкранный режим |
| `T` | Закрепить счётчик времени на экране |
| `P` | Картинка в картинке |
| `W` | Подогнать окно под видео (однократно, без фиксации пропорций) |
| `?` (удерживать) | Показать сочетания клавиш |
| `C` | Переключение субтитров |
| `A` | Переключение аудиодорожек |
| `D` | Чересстрочность (`auto` / `yes` / `no`) |
| `R` | Соотношение сторон |
| `J` | Определить и обрезать чёрные поля |
| Правый клик | Контекстное меню |
| Двойной клик | Полноэкранный режим |
| `Esc` | Выйти из полноэкранного режима / закрыть меню |

Действие «Показать / скрыть окно» доступно в настройках клавиш, но по умолчанию
не назначено.

## Настройки

Все пользовательские файлы лежат в `~/.config/luma/`:

| Файл | Назначение |
| --- | --- |
| `luma.conf` | Настройки приложения (INI) |
| `mpv.conf` | Дополнительные параметры mpv, подключаются при запуске |
| `yt-dlp.conf` | Параметры yt-dlp при открытии ссылок |
| `shortcuts.conf` | Локальные и глобальные привязки клавиш |
| `playlists/*.json` | Сохранённые именованные плейлисты |

Журналы пишутся в `~/.cache/luma/`: `luma.log`, `mpv.log` и `yt-dlp.log`.
Для каждого компонента можно выбрать `off`, `error`, `info` или `debug` на
странице **Отладка** в настройках либо в секции `[debug]` файла `luma.conf`.
Позиции просмотра хранятся в `~/.cache/luma/playback-positions.json` (последние
500 файлов, не старше 90 дней).

Секции `luma.conf`:

```ini
[ui]
remember_volume=true
default_volume=80
volume=80
language=ru              # en, ru
single_instance=true
resume_playback=true
notifications=true
append_to_playlist=false
control_bar_mode=float  # hidden, float, pinned
show_panels_fullscreen=true
show_chapter_markers=true

[playlist]
mode=sequential          # только для «По умолчанию»: sequential, repeat, shuffle, stop

[debug]
luma=info                # off, error, info, debug
mpv=off
ytdlp=off

[window]
width=960
height=600

[subtitles]
font=sans-serif
size=55
bold=false
color=#FFFFFFFF         # #RRGGBB или #AARRGGBB
border_size=3
border_color=#FF000000
background=false
position=100            # 0..100, 100 = низ экрана
ignore_file_style=false
```

Эти ключи пишет вкладка «Субтитры» в настройках; выбор шрифта показывает системные
шрифты.

Вкладка «Воспроизведение» хранит `hwdec` и `ao` в `mpv.conf` в синтаксисе mpv
(`hwdec=...`, `ao=...`); автоматический аудиовыход — это отсутствие строки `ao`.
В старых версиях эти значения лежали в `luma.conf` в секции `[playback]`; при первом
запуске они переносятся в `mpv.conf`, а ключи из `luma.conf` удаляются. `no` в `hwdec`
отключает аппаратное декодирование.

`yt-dlp.conf` — по одной опции на строку, читается при каждой ссылке. Качество видео и
прокси задаются в *Настройки → Воспроизведение*; Luma записывает их в этот файл, сохраняя
остальные ваши строки, например:

```ini
--no-playlist
--format=bestvideo[height<=1080]+bestaudio/best[height<=1080]
--proxy=socks5://127.0.0.1:1080
```

Прокси задаётся типом (`SOCKS5`, `SOCKS5h`, `HTTP`, `HTTPS`) и адресом в виде
`host:port`. yt-dlp использует его для получения потока. Для SOCKS5 Luma дополнительно
поднимает локальный HTTP-мост: mpv качает поток (включая перемотку и Range-запросы) через
него, поэтому работает даже SOCKS-прокси без дополнительных утилит. HTTP-прокси
передаётся mpv напрямую. Файлы не скачиваются.

В разделе *Воспроизведение → Интернет-воспроизведение* также показывается состояние
компонентов YouTube. Deno ставится пакетным менеджером системы, а `yt-dlp-ejs` можно
установить в `~/.local/share/luma` кнопкой в этом разделе, не трогая системный Python.
Luma сама передаёт Deno в yt-dlp и не читает куки браузера. Пакеты скачиваются с PyPI
только по нажатию кнопки и сохраняют собственные лицензии (yt-dlp — Unlicense;
yt-dlp-ejs — Unlicense/MIT/ISC).

## Локализация

Строки лежат в `.ts`-файлах в `locales/` (`en`, `ru`). Японский и китайский временно
отключены. Чтобы добавить язык: создайте `locales/<lang>.ts`, добавьте его в
`qt_add_translations(...)` и в список `install(FILES ...)` в `CMakeLists.txt`, а также
в список языков в `qml/SettingsDialog.qml`.

Переводы этого README — в [`docs/readme/`](README.md).

## Если что-то не работает

- **Запуск второй копии ничего не делает.** Включён режим одного экземпляра: аргументы
  передаются уже запущенному плееру, а новый процесс завершается. Закройте работающий
  экземпляр или задайте `single_instance=false` в `luma.conf`.
- **X11 не поддерживается.** Luma работает только в сессиях Wayland (KWin, GNOME,
  Sway, Hyprland, …); поддержка X11 не планируется. При запуске она проверяет наличие
  Wayland и завершается с ошибкой, если его нет, поэтому запускайте её в сессии
  Wayland. В AppImage также не входит xcb-плагин Qt.
- **Ошибка импорта QML при запуске.** Установите `kirigami` и `qqc2-desktop-style`.
- **Трансляция не находит устройства.** Проверьте, что установлены `avahi` и `ffmpeg`,
  а телевизор в той же сети.

## Версионирование

Luma использует версии `MAJOR.MINOR.PATCH`. Единственный источник версии —
файл [`VERSION`](../../VERSION); его читают `CMakeLists.txt`, `main.cpp`, `PKGBUILD` и
`build-appimage.sh`. Правила для мажорных, минорных, патч-версий и пересборок
описаны в [`VERSIONING.md`](../../VERSIONING.md).

Luma распространяется по лицензии **GPL-3.0-or-later**. Встроенный код `mpvqt/` —
LGPL-2.1-only (см. заголовки файлов), его лицензионные заголовки сохранены.
